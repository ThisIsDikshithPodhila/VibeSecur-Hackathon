# Presenter browser check

Run `npm run test:browser` from `apps/presenter` only when an authorized browser slot is available. The script uses the installed Playwright Chromium by default; set `CHROME_PATH` only when a specific browser binary is required. `PRESENTER_URL` selects the presenter endpoint. Without `PRESENTER_ACCESS_CODE`, it checks only the sign-in surface and reports authenticated checks as not tested.

With a presenter access code and existing saved runs, the check first verifies that the new-run mode selector defaults to replay and that Live agent can be selected and restored without starting a run. It selects the existing resumed replay run and checks that Repair output, matching Verification, and Deployment/readiness-probe rows are distinct in the persisted UI. It verifies the guidance cue, focus on its exact `aria-controls` target (including the protected receipt below the sticky nav), the three mission-section navigation targets, and that the selected run and cue state survive reload. It checks visible guidance/navigation and horizontal overflow at 1280×800, 820×1180, and 390×844, plus keyboard focus and zero cue motion under reduced-motion emulation. It captures screenshots under `docs/design/browser-check/` with technical details collapsed.

The harness does not create a run or submit mission, replay, repair, resume, approval, or reset commands. It only opens and cancels the existing reset confirmation dialog. A clearly labelled GET-only 503 route fixture checks offline/reconnect copy; it does not mock run results. Unexpected non-GET requests after login, external font requests, page errors, and failed layout/navigation assertions are reported as failures. The harness does not inspect security trace payloads.
