## Boundary evidence profile `owned-demo-v1`

Fresh worker, repair and verifier admissions require gate evidence with `profile:'owned-demo-v1'`, exact pinned image and network identity, `checkedAt` within one hour, and every executor-specific positive and negative control. Legacy evidence is retained for audit but does not satisfy new admissions. Each gate probes only the VibeSecur-owned synthetic application, controller, verifier, relay, bridge gateway and hosted demo HTTPS endpoint. It does not contact cloud-provider metadata/platform endpoints or any third-party service.

The gate records `routeProof` from the sandbox network namespace: expected internal subnet, IPv4/IPv6 route tables, `noDefaultRoute`, `onlyExpectedInternalRoutes` and `providerRouteDenied`. The named provider-address conclusion is a route/topology inference, not a live request. Admission requires `coverage.providerRouteDenied:true` and all other applicable measured controls. `coverage.metadataDenied` and `coverage.azurePlatformDenied` are `null` to make the unmeasured live probes explicit. A host-positive owned HTTPS preflight and a sandbox direct TCP attempt to the same owned VM address establish public egress denial only when the kernel returns `ENETUNREACH`; timeout, refused connection, DNS or TLS failure is blocked infrastructure evidence, never a prevention pass. OpenShell may additionally use an explicit effective-policy deny for that owned endpoint. Gate files state their method and limitations; no Docker result claims OpenShell equivalence.
