# Tablet presenter runbook

Open the configured HTTPS URL and sign in using the privately supplied presenter access code. No terminal is needed on the tablet. All suppliers, accounts, and payments are synthetic.

1. In Chat, ask Maya to summarize an invoice or process the authorized supplier payment. Suggestions populate the composer; edit and send them yourself.
2. Read the work panel for actual recorded tool activity. A loading indicator alone is not evidence that work occurred.
3. If an action is blocked, compare the actual amount and destination shown in the intervention. Open **View what happened** for the Control Panel.
4. Read the supported investigation conclusion. Course correction alone does not imply a software defect or a need for repair.
5. When a saved remediation plan is available, review/edit it and submit **Fix it** to the configured executor. Keep repair prepared, independently verified, deployed, and resumed outcomes distinct.
6. Return to Maya and check the actual payment outcome. A later legitimate payment must be distinguished from the earlier blocked attempt.
7. Linear/Jira issue creation requires a connected provider and an editable draft. An unavailable connector does not create tickets.

Refresh should restore server-held run state; check the current status before resubmitting anything. If the connection fails, wait for reconnection or contact the operator. Do not describe replay, incomplete gates, or missing runtime connections as live success. Rehearse this entire flow against the deployed snapshot before presenting it.
